## 정확도 숫자 읽는 법

- **찾을 때 이미 HaGeZi 에 있음**: 우리가 찾은 날 이미 HaGeZi 도박 목록에 있던 것. 같은 것을 잡았다는 뜻입니다.
- **새로 찾음 → 그중 나중에 HaGeZi 에 오름 → 비율**: HaGeZi 보다 먼저 찾았고 나중에 HaGeZi 도 도박으로 판정한 비율입니다.
- **확인 못 함**: 찾은 날 도박 목록을 못 받아 비교하지 못한 것. 비율 계산에서 뺍니다.
- HaGeZi 는 한글 주소를 거의 싣지 않습니다(2026-10-31 기준 62만 개 중 14개). 그래서 한글 분류는 비율보다 **이름을 눈으로 보는 것**이 더 정확합니다.

## 안전과 서버 예의

- **후보 주소에는 절대 접속하지 않습니다.** HTTP 요청도 DNS 조회도 없고, 이름 글자만 봅니다.
  코드도 정해진 두 파일 말고는 받지 못하게 막혀 있습니다(`fetch.py`, 테스트로 고정).
- 받는 곳은 GitHub 에 있는 HaGeZi 파일 두 개뿐입니다(절대준수 §2).
  - 새 도메인 목록: `hagezi/nrd` 의 `domains/nrd7.txt`. 7일치 약 267만 개이고, 압축해서 약 15MB 를 받습니다.
  - 도박 목록 전체판: `gambling-onlydomains.txt`. 약 62만 개이고, 압축해서 약 2.6MB 를 받습니다.
  - 하루 한 번만 받고, ETag 로 바뀐 것만 받습니다.
  - 두 요청 사이에 3초 쉽니다.
  - 403/429 를 받으면 그 서버에는 하루 동안 묻지 않습니다. 재시도나 우회는 하지 않습니다.
  - 받은 파일이 10만 개보다 적으면 깨진 것으로 보고, 그날은 쓰지 않습니다.
- 실행 중에 AI 를 쓰지 않고, 비밀값도 필요 없습니다. 공개 저장소의 GitHub Actions 라 무료입니다.
- 출처와 라이선스: HaGeZi 의 두 목록은 GPL-3.0 이고, 새 도메인의 원자료는 Stamus Labs 입니다.
  우리는 걸러 낸 후보만 올리고 원본 전체는 올리지 않습니다.
- 자료원을 고른 근거(2026-11-01 오너 선택): WhoisDS 무료판은 약관이 서로 엇갈려 쓰지 않았습니다.
  인증서 기록(CT)은 공식 검색 API 가 없고 서버 부담 위험이 있어 쓰지 않았습니다.
  ICANN CZDS 는 가입·승인·비밀값이 필요해 쓰지 않았습니다.

## GitHub Actions 동작

- 매일 한국 시간 19:17 쯤 돕니다. GitHub 이 바쁘면 늦어지거나 가끔 건너뛸 수 있습니다(GitHub 공식 안내).
  새 도메인 목록이 7일치라, 하루 건너뛰어도 다음 날 같이 잡힙니다.
- `collector/` 를 고쳐 main 에 올려도 한 번 돕니다. 시험이 실패하면 수집하지 않습니다.
- 결과는 `collector-data` 브랜치에만 저장합니다. main 에는 봇이 쓰지 않으니, PC 에서 `git push origin main` 할 때 방해가 없습니다.
- GitHub 은 공개 저장소에 60일 동안 활동이 없으면 예약 실행을 저절로 끕니다(공식 안내).
- 받기에 실패하면 그날 실행이 빨간불로 끝납니다. GitHub 은 워크플로 파일을 마지막으로 올린 계정에 알림을 보냅니다(알림 설정에 따라 메일). 이유는 `daily.tsv` 에 적힙니다.

## 차단 스위치 (수집기 쪽은 2026-11-01 만들어 둠, 오너 승인 — 앱 쪽은 개발 세션)

목표: 관찰 결과가 좋으면 **AI 없이 GitHub 웹에서 한 줄만 바꿔** 차단을 켜고 끈다.

1. **스위치 파일** [`collector/차단스위치.txt`](차단스위치.txt) (main 브랜치). `lists/AUTO_UPDATE.txt` 처럼 GitHub 웹에서 고칩니다.
   분류마다 `켜기`/`끄기` 를 고르고, 처음에는 전부 `끄기` 입니다(시험이 지킴).
   한 분류의 줄이 모두 정확히 `켜기`(또는 `on`)일 때만 켜집니다. `켬`·`켜기요` 처럼 애매하거나, 같은 분류에 켜기와 끄기가 섞여 있거나, 파일이 없으면 끄기로 봅니다.
2. **봇이 차단 파일을 만듦**: 매일 실행할 때, 그리고 스위치를 고쳐 main 에 저장한 직후에 `collector-data` 브랜치의 `collector/block.txt` 를 다시 씁니다(`block.py`).
   - 켜진 분류의 후보만 넣습니다. 모두 끄기면 설명 줄만 있는 빈 목록이 됩니다(파일은 늘 있음).
   - `lists/allow.txt` 에 있는 주소와 그 하위 주소, 합법 공식 사이트는 넣지 않습니다.
   - 안전장치: 켠 분류의 새 후보가 하루 500개를 넘거나 전체가 2만 개를 넘으면, 새로 쓰지 않고 어제 파일을 둔 채 빨간불로 알립니다(`daily.tsv` 의 `차단파일` 칸에 '멈춤').
   - 형식: `#` 설명 줄 + 한 줄에 주소 하나.
3. **앱이 그 파일을 받음** (앱 변경, **한 번만** 필요 — 개발 세션 담당, 아직 안 함): `ListSources.kt` 에 목록 하나를 더합니다.
   - 주소는 `raw.githubusercontent.com/gOmgOmKing/family-shield/collector-data/collector/block.txt` 입니다.
   - 하루 한 번 받고, 1MB 상한, 최소 0개(빈 목록이 정상 상태)입니다.
   - 허용 목록이 여전히 우선합니다(§9).
   - 이 앱 변경은 새 버전으로 나가므로, 부모님 폰 두 대에 한 번 설치해야 합니다(자동 업데이트가 꺼져 있어 오너가 직접, `새버전_설치방법.md`).
4. **끄기**: 스위치를 `끄기` 로 바꾸면 봇이 빈 목록을 쓰고, 다음 받기 때 폰에서 빠집니다.

검토했지만 쓰지 않은 방식: 봇이 main 의 `lists/block.txt` 에 직접 쓰기.
앱을 안 고쳐도 되지만 세 가지 문제가 있습니다.
- 봇이 main 에 매일 쓰면, PC 에서 올릴 때마다 먼저 내려받아야 합니다.
- 오너가 손으로 관리하는 목록에 자동 후보가 섞입니다(§1 "줄마다 출처").
- 처음 맡긴 일에서 `lists/` 에는 넣지 않기로 했습니다.
