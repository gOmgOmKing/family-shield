# 토토 후보 관찰기 (관찰 전용)

매일 새로 등록된 도메인 이름 중에서 **한국 불법 토토·도박으로 보이는 것**을 골라 기록합니다.
**아직 차단에는 쓰지 않습니다.** 앱과 `lists/` 에는 아무 영향이 없습니다.
차단에 넣을지는 1~2주 숫자를 본 뒤 오너가 따로 정합니다.

## 결과 보는 곳

👉 **https://github.com/gOmgOmKing/family-shield/tree/collector-data/collector**

파일 목록 아래에 요약표가 자동으로 보입니다.

| 파일 | 내용 |
|---|---|
| `README.md` (요약) | 분류별 숫자, 최근 실행 기록, 최근 후보 100개(한글 주소는 한글로 풀어서 보여 줌) |
| `candidates.tsv` | 지금까지 찾은 후보 전체. 처음 찾은 날, HaGeZi 도박 목록에 오른 날 포함 |

그래서 `main` 은 그대로이고, 오너가 PC 에서 `git push origin main` 할 때 방해가 되지 않습니다.

## 언제 무엇을 판단하나

**2026-11-15 무렵(2주 뒤)** 요약표를 보고 분류별로 정합니다.

1. **이름을 눈으로 보기**: 그 분류의 '최근 후보'가 거의 다 도박 주소로 보이는지 확인합니다.
   한글 주소는 한글로 풀어 보여 주니 이름만 봐도 알 수 있습니다. **후보 주소에 직접 들어가 보지는 마세요**(악성 사이트일 수 있음).
2. **비율 보기**: 새로 찾은 후보 중 나중에 HaGeZi 도박 목록에도 오른 비율입니다. 높을수록 맞게 찾은 것입니다.
   단, HaGeZi 는 한글 주소를 거의 싣지 않습니다(2026-10-31 기준 62만 개 중 14개). 그래서 한글 분류는 비율이 낮게 나와도 틀렸다는 뜻이 아닙니다.
3. **양 보기**: 하루에 몇 개쯤 나오는지 봅니다. 첫날 7일치를 시험으로 돌렸을 때는 후보가 100개(하루 약 14개)였습니다.

차단에 넣기로 하면 그때 별도 작업으로 앱이 받는 목록에 연결합니다(새 기능이라 오너 승인 후, 절대준수 §8).

- `toto` 만 들어간 이름: 일본 변기 회사 TOTO, 인도네시아 도박('togel')과 구분이 안 됩니다.
- 번호만 바꾼 영어 이름 묶음(예: `○○toto12`, `○○bet655`): 대부분 인도네시아·튀르키예 사이트입니다.

- `bet` 만 들어간 이름: alphabet, better 등. `.kr` 주소에서만 보고, 그때도 이런 영어 낱말은 지우고 봅니다.
- `안전`, 그냥 `주소`, `새주소`: 안전제일·도로명 새주소처럼 일반 낱말이라 뺐습니다.

오탐 예시는 모두 [tests/test_classify.py](tests/test_classify.py) 에 고정돼 있습니다.

## 안전과 서버 예의

- **후보 주소에는 절대 접속하지 않습니다.** HTTP 요청도 DNS 조회도 없고, 이름 글자만 봅니다.
  코드도 정해진 두 파일 말고는 받지 못하게 막혀 있습니다(`fetch.py`, 테스트로 고정).
- 받는 곳은 GitHub 에 있는 HaGeZi 파일 두 개뿐입니다(절대준수 §2).
  - 새 도메인 목록: `hagezi/nrd` 의 `domains/nrd7.txt`. 7일치 약 267만 개이고, 압축해서 약 15MB 를 받습니다.
  - 도박 목록 전체판: `gambling-onlydomains.txt`. 약 62만 개이고, 압축해서 약 2.6MB 를 받습니다.
  - 하루 한 번만 받고, ETag 로 바뀐 것만 받습니다.
  - 두 요청 사이에 3초 쉽니다.
  - 403/429 를 받으면 그 서버에는 하루 동안 묻지 않습니다. 재시도나 우회는 하지 않습니다.
- 실행 중에 AI 를 쓰지 않고, 비밀값도 필요 없습니다. 공개 저장소의 GitHub Actions 라 무료입니다.
- 출처와 라이선스: HaGeZi 의 두 목록은 GPL-3.0 이고, 새 도메인의 원자료는 Stamus Labs 입니다.
  우리는 걸러 낸 후보만 올리고 원본 전체는 올리지 않습니다.

## 켜기·끄기·직접 돌리기

GitHub 저장소 → **Actions** → 왼쪽 **토토 후보 관찰**에서 합니다.
- 직접 한 번 돌리기: **Run workflow**
- 끄기: 오른쪽 위 **…** → **Disable workflow**
- 다시 켜기: 같은 자리의 **Enable workflow**

알아 둘 점:
- 매일 한국 시간 19:17 쯤 돕니다. GitHub 이 바쁘면 늦어지거나 가끔 건너뛸 수 있습니다(GitHub 공식 안내).
  새 도메인 목록이 7일치라, 하루 건너뛰어도 다음 날 같이 잡힙니다.
- GitHub 은 공개 저장소에 **60일 동안 활동이 없으면 예약 실행을 저절로 끕니다**(공식 안내). 그때는 위의 Enable workflow 로 다시 켭니다.
- 받기에 실패하면 그날 실행이 빨간불로 끝납니다. GitHub 은 워크플로 파일을 마지막으로 올린 계정에 알림을 보냅니다(알림 설정에 따라 메일). 이유는 `daily.tsv` 에 적힙니다.
