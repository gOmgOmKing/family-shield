# 절대준수 — 바뀌지 않는 원칙

이 문서의 규칙 본문은 여기에만 둔다. 다른 문서는 §번호로 가리키기만 한다.

## §1 없는 데이터를 지어내지 않는다 · 실패는 화면에

- 모르는 값은 모른다고 둔다(`null`). 기본값·추정으로 메우지 않는다.
  예: 상시 VPN 여부를 알 수 없는 안드로이드 9 이하에서는 도우미에 "❔ 확인할 수 없음"으로 보인다.
- 실패는 **부모님 폰 화면**에 보인다. 로그만 남기는 것은 조치가 아니다.
  예: 목록 받기 실패 → 메인 화면 빨간 글씨 + 목록별 오류 문장. VPN 멈춤 → 화면 + 알림.
- 차단 주소를 지어내지 않는다. `lists/` 에 넣는 주소는 검증된 출처(List-KR, HaGeZi 등)에 있거나
  직접 확인한 것만 넣고, 줄마다 출처를 적는다.

## §2 상대 서버에 무리를 주지 않는다

- 목록은 차례로 받고(동시 요청 없음), 요청 사이 2~3초 쉰다.
- ETag 로 "바뀐 것만" 받는다(안 바뀌면 서버가 304 로 짧게 답함).
- 403/429 를 받으면 그 서버에는 **하루 동안 묻지 않는다**. 재시도·우회(User-Agent 바꾸기 등) 금지.
- 일정은 필요한 만큼만: 직접 관리 목록 6시간, 커뮤니티 목록·새 버전 확인 하루 1번.
- 접속하는 곳 전체 목록: [전체흐름.md](전체흐름.md) "밖으로 나가는 접속".

## §3 보안에는 타협하지 않는다

- 앱 업데이트는 **서명 열쇠로 서명된 APK만** 설치된다(안드로이드가 강제). GitHub 이 털려도 가짜 앱으로 못 바뀐다.
  앱도 설치 전에 패키지 이름·버전·서명을 한 번 더 확인한다.
- 폰은 **받기만** 한다. 방문 기록·차단 기록은 폰 밖으로 나가지 않는다. 앱은 어떤 서버에도 무엇을 보내지 않는다.
- 제3자 DNS 서버(구글·클라우드플레어 등)를 쓰지 않는다. 폰이 연결된 망이 알려 준 DNS 만 쓴다.
- 저장소는 공개다. 개인정보·비밀값을 넣지 않는다.

## §4 비밀값 (서명 열쇠)

- 서명 열쇠는 `keystore/family-shield.jks` + `keystore.properties` 두 파일이다. **PC 에만 있고 GitHub 에 올리지 않는다**(`.gitignore`).
- 비밀번호는 `scripts/make-keystore.sh` 가 무작위로 만들어 `keystore.properties` 에만 적는다. 코드·문서·로그·화면·커밋에 값을 남기지 않는다.
- **두 파일을 잃으면** 부모님 폰은 새 버전을 받지 못한다(앱을 지우고 새로 깔아야 함). 반드시 두 곳 이상 백업.
- 열쇠를 새로 만들지 않는다. `make-keystore.sh` 는 이미 있으면 아무것도 안 한다.

## §5 개인정보

- 이 앱은 부모님 폰 두 대 전용이다. 저장소·릴리스·문서에 부모님 정보(이름·번호·위치)를 넣지 않는다.
- 차단 기록(최근 막은 주소)은 폰 메모리에만 있고 앱을 끄면 사라진다. 막은 횟수(숫자)만 폰에 저장한다.

## §6 중복을 만들지 않는다 — 값마다 한 곳

| 값 | 유일한 위치 |
|---|---|
| 받는 목록 주소·크기 상한·최소 개수 | `app/src/main/java/com/familyshield/app/lists/ListSources.kt` |
| 정기 작업 주기 | `app/src/main/java/com/familyshield/app/Jobs.kt` |
| GitHub 저장소 이름 | `gradle.properties` 의 `shield.githubRepo` |
| 자동 업데이트 켜기/끄기 | `lists/AUTO_UPDATE.txt` 맨 아래 줄 (GitHub 에서 오너가 고침, 기본 끄기) |
| 새 버전 받는 주소 | `app/build.gradle.kts` (release 는 항상 GitHub Releases, debug 시험 빌드만 `-Pshield.testUpdateBaseUrl` 로 PC 지정 가능) |
| 앱 버전 | `version.properties` (릴리스 스크립트가 올림) |
| 화면 글자 크기·색 | `app/src/main/java/com/familyshield/app/ui/Ui.kt` |
| 가짜 DNS 주소 | `app/src/main/java/com/familyshield/app/vpn/ShieldVpnService.kt` |

## §7 코드리뷰·재검토는 착수 전에 오너에게 묻는다 (토큰을 크게 씀)

## §8 새 기능은 오너 승인 후 실전 반영 (긴급 복구는 예외)

새 릴리스(부모님 폰에 깔리는 것)는 오너가 `scripts/release.cmd` 로 직접 올린다.

## §9 이 앱의 고정 결정

1. **가족이 보낸 쇼핑 링크는 열려야 한다.** 그래서 `link.coupang.com`, `coupa.ng` 는 막지 않는다
   (파트너스 링크와 일반 공유 링크가 같은 주소를 쓰는 것으로 보임 — `lists/coupang.txt` 설명 참고).
2. **공용 CDN 을 막지 않는다.** 예: `t1.daumcdn.net`(티스토리 사진), `blogger.googleusercontent.com`(블로그스팟 사진).
   `OwnListsTest` 가 이 규칙을 지킨다 — 어기면 테스트가 빨간불.
3. 허용 목록이 차단 목록보다 우선한다(가족 링크를 살리는 마지막 수단).
4. 허용 목록은 GitHub 의 `lists/allow.txt` 로 고친다(폰에서 비밀번호로 고치는 방식은 쓰지 않음).
5. 유지보수에 AI·토큰이 들지 않게: 커뮤니티 목록은 자동 갱신, 직접 목록과 자동 업데이트 스위치는 오너가 GitHub 에서 손으로, 앱은 GitHub Releases 로 스스로 업데이트.
6. 카카오톡도 다른 앱처럼 걸러진다(폰 전체 DNS 차단, 인앱 브라우저 포함). 오너 결정 2026-10-31: "일단은 막아보자,
   써 보고 생각해 볼게" — 제외 스위치는 만들지 않는다. 나중에 필요하면 `ShieldVpnService` 의 `addDisallowedApplication`
   한 줄로 앱별 제외를 더할 수 있다(새 기능 → 오너 승인 후).

## §10 코드 작성 순서

- 테스트를 먼저 쓰고 실패를 본 뒤 구현한다(TDD). 판단 로직은 안드로이드 없이 시험되는 순수 코드로 분리한다.
- 검사·가드를 만들면 일부러 망가뜨려 테스트가 잡는지 확인한다(사보타주 검증). 결과표는 [이력.md](이력.md).
