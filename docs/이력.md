### 확인한 사실 (2026-10-31)
- HaGeZi wildcard 목록 3개 주소·크기 확인: Pro 4.1MB/213,292개, Pop-Up 0.9MB/50,966개, TIF mini 3.5MB/193,524개. 모두 ETag 지원.
- List-KR 에 DNS 형식이 있다: `cdn.jsdelivr.net/npm/@list-kr/filterslists@latest/dist/filterslist-DNS.txt` (약 390줄).
- HaGeZi Pro 는 `googleadservices.com`, `ad.doubleclick.net`, `adservice.google.com` 을 막지 않는다 → List-KR·직접 목록이 메운다.
- 공용 CDN(`t1.daumcdn.net`, `blog.kakaocdn.net`, `blogger.googleusercontent.com` 등)은 어느 목록도 막지 않는다.

## #3 — 2026-11-01 · 자동 업데이트를 스위치로 끄고 켜게 함

### 경위
Play 프로텍트가 스스로 업데이트를 막아(#2) 오너가 "업데이트는 오너가 직접 설치(가)"로 결정, 자동 업데이트는 **끄되**
"껐다 켰다 하는 곳을 헤매지 않고 바로 찾을 수 있게" 해 달라고 함. (한 번은 기능을 통째로 지웠다가, 오너 뜻이 '스위치'라 다시 살림)

### 처방
- 스위치 파일 `lists/AUTO_UPDATE.txt` (맨 아래 줄 `끄기`/`켜기`, 기본 끄기). 직접 관리 목록처럼 6시간마다 GitHub 에서 받는다(`ListKind.SETTING`, 차단 규칙에는 안 들어감).
- `UpdateSwitch.isOn`: '#' 설명 줄을 뺀 첫 줄이 정확히 `켜기`(또는 on)일 때만 켜짐, 애매하면 꺼짐. 꺼져 있으면 `SelfUpdater` 는 서버에 요청하지 않는다.
- 찾기 쉽게: GitHub 첫 화면 `README.md` 맨 위, `새버전_설치방법.md` 맨 위, `CLAUDE.md` 맨 위, 앱 메인 화면 버전 바로 밑 `자동 업데이트: 꺼짐/켜짐`. 앱 버전도 제목 바로 밑에 표시(전화로 확인용).
- 설정 도우미 ⑤ '새 버전 설치 허락'은 스위치가 꺼져 있으면 "지금은 필요 없음"으로 표시.

### 검증
- TDD: `UpdateSwitchTest` 5개 먼저 작성·실패 확인 후 구현. `OwnListsTest` 에 "스위치는 꺼진 채로 나간다", "스위치 파일은 차단 주소를 더하지 않는다" 추가. 단위 테스트 79개 통과, lint 오류 0.
- 사보타주: 설명(#) 줄의 켜기를 켜짐으로 읽게 → 🔴 잡음 / '켜기'가 들어 있기만 하면 켜짐 → 🔴 잡음 / 스위치 파일을 `켜기`로 내보냄 → 🔴 잡음 /
  스위치 파일을 차단 목록에 섞음 → 🟢 못 잡음(파일에 주소가 없어 동작이 바뀌지 않음 — 결함 아님).
- 에뮬레이터(안드로이드 9, 시험 빌드 + PC 시험 서버): 꺼짐 → 업데이트 작업을 강제로 돌려도 서버 요청 0건 / 켜짐(앱 안 스위치 파일을 `켜기`로) →
  version.txt·APK 를 받아 설치 창이 바로 열림. 화면에 `자동 업데이트: 꺼짐`(회색)/`켜짐`(초록) 표시 확인.

### 하지 않은 것
- GitHub 에서 실제로 스위치를 바꿔 보는 시험: 저장소가 아직 없어 못 함(앱 안 파일을 직접 바꿔 같은 경로를 시험).

오너가 `gh` 2.103.3 을 직접 설치하고 웹 로그인(gOmgOmKing, 권한 repo·workflow·read:org·gist).
오너: "깃 허브에 올리는건 AI를 써서 올라가는게 아니라 자동화 시스템을 만들어주면 좋을것 같아" → `scripts\release.cmd` 더블클릭만으로 막힘 없이 되는지 점검(실제 릴리스는 하지 말 것).

### 처방 (`scripts/release.sh`)
- gh 를 PATH 에서 못 찾으면 기본 설치 위치(`C:\Program Files\GitHub CLI`)도 본다. 새로 깐 프로그램은 컴퓨터를 다시 켜기 전까지 PATH 에 안 잡힐 수 있어서.
- JDK: `JAVA_HOME` 보다 JDK 17(Eclipse Adoptium)을 먼저 쓴다. Android Studio 의 JDK 25 는 Gradle 8.14 에 너무 새것.
- main 브랜치인지 확인, `local.properties` 가 없으면 조용히 끝나지 않고 안내.
- 버전 숫자를 올리기 전에 `git pull --ff-only origin main` — GitHub 웹에서 목록을 고친 뒤 실행하면 마지막 올리기가 거절되고 이 PC 에만 커밋·태그가 남던 문제를 막는다.
- 올리기 단계에서 실패하면 영어 오류만 남지 않게 한국어 안내를 띄운다.

### 검증
- 더블클릭과 같은 방식(cmd → Git Bash `--login`)으로, 스크립트의 준비물 확인 부분만 떼어 실행:
  gh(기본 위치에서 찾음)·`gh auth status` 로그인·JDK 17·apksigner 모두 통과. 이 창의 환경에서는 gh 가 PATH 에 없었다 — 고치기 전 같은 환경에서 "gh NOT on PATH" 확인.
- "저장하지 않은 변경" 검사도 정상으로 멈춤(그때 다른 세션이 `collector/` 를 고치는 중이었음).
- 전체 단위 테스트 81개 통과. 스크립트 문법 검사(`bash -n`) 통과.

### 하지 않은 것
- 실제 릴리스(지시대로 안 함) — 그래서 `gh release create` 업로드, 태그 올리기, 한글 입력(바뀐 내용 한 줄)은 미확인.
- GitHub 웹 수정 뒤 실행하는 경우를 실제로 재현하지는 않음(`git pull --ff-only` 동작에 기댐).
